## 面板形态

### 搜索面板形式

| Option | Description | Selected |
|--------|-------------|----------|
| 屏幕中央浮层（推荐） | 类似 Spotlight/Alfred 的体验，按快捷键后在屏幕中央弹出浮层，搜索完成后自动消失。优点：快速、不干扰当前页面；缺点：需要自定义实现覆盖层。 | ✓ |
| 侧边栏面板 | Chrome Extension 的 Side Panel API，固定在浏览器侧边栏。优点：原生支持、不遮挡内容；缺点：需要手动打开/关闭，不够快捷。 | |
| Popup 弹窗 | 点击扩展图标弹出的小窗口。优点：实现简单；缺点：窗口太小，展示内容有限，不适合快速浏览大量结果。 | |
| 新标签页 | 在新标签页打开完整的搜索界面。优点：空间充足；缺点：打开速度慢，打断当前工作流。 | |

**User's choice:** 屏幕中央浮层（推荐）
**Notes:** 用户选择了类似 Spotlight/Alfred 的体验，快速且不干扰当前工作流。

### 快捷键选择

| Option | Description | Selected |
|--------|-------------|----------|
| Ctrl+Shift+Space（推荐） | Chrome Extension 的 commands API 支持自定义快捷键，用户可以在 chrome://extensions/shortcuts 中修改。推荐使用 Ctrl+Shift+Space（Windows/Linux）或 Cmd+Shift+Space（Mac），避免与系统快捷键冲突。 | |
| Ctrl+Space | 更简洁的快捷键，但可能与某些应用冲突（如 Spotlight 在 Mac 上默认是 Cmd+Space）。 | ✓ |
| 由用户自定义 | 让用户自己在 Chrome 设置中配置，扩展只提供默认建议。 | |

**User's choice:** Ctrl+Space
**Notes:** 用户选择了 Ctrl+Space，并提到已经安装了 Raycast（快捷键是 Alt+Space），不会冲突。

### 浮层实现方式

| Option | Description | Selected |
|--------|-------------|----------|
| Content Script 注入浮层（推荐） | 在当前标签页注入 Content Script，创建一个覆盖整个页面的浮层。优点：实现简单，可以直接在当前页面上显示；缺点：可能与某些网站的样式冲突，需要处理 z-index 和 CSS 隔离。 | ✓ |
| 独立窗口 | 打开一个独立的 HTML 页面（通过 chrome.windows.create 或 chrome.tabs.create），设置为无边框窗口或特殊样式。优点：完全独立，不受网站影响；缺点：实现复杂，可能有性能开销。 | |
| Side Panel（自动打开） | 使用 Chrome Extension 的 Side Panel API，但通过快捷键自动打开/关闭。优点：原生支持；缺点：位置固定在侧边，不是屏幕中央。 | |

**User's choice:** Content Script 注入浮层（推荐）
**Notes:** 用户选择了 Content Script 注入浮层的方式，这是最常见的实现方式。

## 搜索交互

### 搜索触发方式

| Option | Description | Selected |
|--------|-------------|----------|
| 实时搜索（推荐） | 用户每输入一个字符就立即搜索并更新结果，类似 Spotlight/Alfred 的体验。优点：即时反馈，体验流畅；缺点：需要做好性能优化（debounce）。 | |
| 按回车搜索 | 用户输入完成后按回车键才触发搜索。优点：性能开销小；缺点：需要额外操作，不够快捷。 | |
| 混合模式 | 结合两者：输入时实时显示结果，按回车确认选择第一个结果。 | ✓ |

**User's choice:** 混合模式
**Notes:** 用户选择了混合模式，输入时实时显示结果，按回车确认选择第一个结果。

### 键盘导航支持

| Option | Description | Selected |
|--------|-------------|----------|
| 完整键盘支持（推荐） | 用户可以用上下方向键在搜索结果中移动选择，按回车打开选中的结果，按 Esc 关闭面板。这是 Spotlight/Alfred 的标准体验。 | ✓ |
| 仅鼠标操作 | 只支持鼠标点击选择结果，不支持键盘导航。实现简单，但体验不够流畅。 | |
| 键盘+鼠标混合 | 支持上下键导航，但也可以直接鼠标点击。两种方式都可以使用。 | |

**User's choice:** 完整键盘支持（推荐）
**Notes:** 用户选择了完整键盘支持，可以完全通过键盘操作。

### 关闭面板方式

| Option | Description | Selected |
|--------|-------------|----------|
| Esc 或点击外部（推荐） | 按 Esc 键关闭面板，或者点击浮层外部区域（背景遮罩）也可以关闭。这是最常见的交互方式。 | ✓ |
| 仅 Esc 键 | 只能通过 Esc 键关闭，点击外部不会关闭。适合防止误操作。 | |
| 选择后自动关闭 | 选择结果后自动关闭面板，不需要额外操作。 | |

**User's choice:** Esc 或点击外部（推荐）
**Notes:** 用户选择了 Esc 或点击外部的方式关闭面板。

## 结果展示

### 结果显示内容

| Option | Description | Selected |
|--------|-------------|----------|
| 标题 + URL + 分组（推荐） | 每条结果显示：网页标题（加粗）+ URL（灰色小字）+ 分组名称（带颜色标签）。信息完整，方便识别。 | |
| 标题 + 分组 | 只显示标题和分组，不显示 URL。界面更简洁，但可能难以区分相同标题的网页。 | ✓ |
| 完整信息（含时间） | 显示标题、URL、分组、同步时间。信息最全，但可能显得拥挤。 | |

**User's choice:** 标题 + 分组
**Notes:** 用户选择了标题 + 分组的展示方式，界面更简洁。

### 结果排序方式

| Option | Description | Selected |
|--------|-------------|----------|
| 按相关度排序（推荐） | 根据搜索关键词的匹配程度排序，最相关的结果排在最前面。使用 Fuse.js 等模糊搜索库可以实现。这是最符合用户预期的排序方式。 | ✓ |
| 按时间排序 | 最近同步的网页排在前面，适合查找最近打开的标签页。 | |
| 按分组+相关度 | 先按分组名称排序，再按相关度排序。适合用户习惯按分组浏览的场景。 | |

**User's choice:** 按相关度排序（推荐）
**Notes:** 用户选择了按相关度排序，最匹配的结果排在最前面。

### 结果数量限制

| Option | Description | Selected |
|--------|-------------|----------|
| 显示全部结果 | 显示所有匹配的结果，用户可以滚动查看。适合数据量不大的场景（预计几十到上百条记录）。 | ✓ |
| 限制显示数量（推荐） | 只显示前 10-20 条最相关的结果，避免信息过载。如果用户没找到想要的，可以继续输入关键词缩小范围。这是 Spotlight/Alfred 的常见做法。 | |
| 你决定 | 由 Claude 决定合适的数量。 | |

**User's choice:** 显示全部结果
**Notes:** 用户选择了显示全部结果，可以滚动查看所有匹配的网页。

## 分组过滤

### 过滤实现方式

| Option | Description | Selected |
|--------|-------------|----------|
| 标签按钮（推荐） | 在搜索框上方或下方显示所有分组的标签按钮（带颜色），点击后只显示该分组的结果。再次点击取消过滤。优点：直观、易用；缺点：分组多时占用空间。 | ✓ |
| 下拉菜单 | 使用下拉菜单选择分组，选择"全部"取消过滤。优点：节省空间；缺点：需要额外点击打开下拉菜单。 | |
| 搜索语法 | 在搜索框中输入特殊语法，如 group:工作 或 #工作，来过滤分组。优点：不需要额外 UI 元素；缺点：需要学习语法，不够直观。 | |
| 不需要过滤 | 不提供分组过滤功能，只通过关键词搜索。用户可以输入分组名称作为关键词来筛选。 | |

**User's choice:** 标签按钮（推荐）
**Notes:** 用户选择了标签按钮的方式实现分组过滤。

### 标签按钮位置

| Option | Description | Selected |
|--------|-------------|----------|
| 搜索框上方 | 分组标签显示在搜索框上方，用户先选择分组再搜索。适合分组数量不多的场景。 | |
| 搜索框下方（推荐） | 分组标签显示在搜索框下方、结果列表上方，用户输入关键词后可以进一步过滤。这是最常见的布局。 | ✓ |
| 侧边栏 | 分组标签显示在结果列表的侧边（左侧或右侧），类似侧边栏的布局。适合分组数量较多的场景。 | |

**User's choice:** 搜索框下方（推荐）
**Notes:** 用户选择了搜索框下方的位置。

### 空状态显示

**User's choice:** 显示全部网页
**Notes:** 当搜索框为空时，显示所有标签组的网页列表，用户可以浏览所有保存的内容。
